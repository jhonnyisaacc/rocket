# MC-010 frozen design — signed-transaction panel and fast-receipt flow test

Parent MC-009. This is a new prospective Solana Pump panel, not a retune of MC-005/MC-006. Their frozen five-second net-flow score repeatedly showed a directional curve-exit-risk association but did not establish profitability or uniformly timely discovery. MC-007/MC-009 observed an all-ones 64-byte zero-signature `logsNotification` with no independent chain transaction. MC-009's third-party creation feed missed 14/58 native Pump launches, so it cannot supply the universe.

Before the new data window, freeze one **600-second**, at most **512 MiB** read-only `confirmed` Pump `logsSubscribe` capture on the Solana Labs mainnet endpoint. Preserve every raw frame, receive clock, checksum, RPC transaction-response attempt, error and manifest bound. Independently index all fully observed interior-slot Pump signatures on `solana-rpc.publicnode.com`. Apply the deterministic signature structure rule from `memecoin_audit.py --quarantine-invalid-signatures`: a notification whose signature is not valid base58, does not decode to exactly 64 bytes, or decodes to 64 zero bytes is retained and reported in quarantine but cannot become a launch, trade or feature row. This rule uses only bytes present at receipt, never later outcomes. Require every **admitted** signature to match the independent chain index and every indexed interior signature to appear in the admitted stream. Report the raw quarantine count separately; any structurally valid unmatched signature, missing indexed signature, collector error, truncated successful log, Pump event decode error, native non-Mayhem state failure or material quote failure fails the data gate. This is a new contract; it does not revise MC-007/MC-009's frozen raw-feed failures.

Preserve the complete CreateEvent universe, including Mayhem, nonnative quote, delayed, transaction-identity-unresolved, short-horizon and unquoteable launches. Record timestamp-to-receipt ages for every decoded create. For a **fast** analytic cohort, require a native-quote non-Mayhem create in verified interior slots, a full 67-second subsequent covered window and CreateEvent timestamp-to-receipt age at most five seconds. This integer-second age is an imperfect necessary screen, not proof of executable latency. Keep delayed names in the denominator as no-decision cases. Confirm creation signature/mint later against signed transaction data for every scored fast name; record retrieval time and exclude unresolved identity from any economic claim.

On names passing the data gate and fast admission, reuse MC-005's exact point-in-time 5-second score `observed_buys_5s - observed_sells_5s`, 10,000,000-lamport trade size, entry at 7 seconds, curve exit at 67 seconds, 200-bps slippage each leg, and 155,000/1,000,000-lamport network-fee scenarios per leg. A curve-unavailable exit has zero recovery **only as a stress scenario**, not as an observed liquidation. Split fast scored names 70/30 chronologically by create receipt, tie breaking by signature. Rank by frozen score and signature within each split; compare the top quartile with the rest for modeled exit unavailability, and with all fast names for costed stress returns. Report exact binomial risk intervals, all unknowns, both quoted-only and zero-recovery returns, and top-group leave-one-out sensitivity. No new cutoff, feature or fee is selected after seeing the cohort.

Minimum evidence for an entry candidate: at least 30 entry-known evaluation names and ten top-quartile names; top unavailable-exit rate below the rest in both development and evaluation; positive top zero-recovery mean exceeding all fast names at **both** fee scenarios in both splits; and a positive held-out top mean after removing its best modeled winner at both fees. These are necessary, not sufficient for a live rule: actual inclusion, priority-fee choice, market impact and alternate exit-route fills remain unmeasured. If any gate fails, report the reason and keep `NO_EDGE_VALIDATED`; do not turn a favorable subgroup into an `ENTER` decision. No signer or order submission is involved.
