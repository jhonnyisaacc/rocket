# MC-008 result — transaction-identified block stream

Status: `REJECTED` as a fast early-event acquisition source. The [design](MC-008-FROZEN.md) fixed a 60-second, 384 MiB read-only `blockSubscribe` test before collection. The feed carried full transaction bytes and achieved exact independent interior signature coverage, but arrived roughly ten seconds after the block timestamp and contained truncated transaction logs. No strategy outcome or entry rank was evaluated.

The `solana-rpc.publicnode.com` block subscription acknowledged at 16:11:14.410983 UTC and ran its requested minute without collector errors. It stored 228 block notifications and 7,553 contained transactions in 229 raw frames, using 75,645,420 bytes of bounded spool space. Its start slot from independent `api.mainnet-beta.solana.com` was 450079099, while the first block notification was slot 450079067, a 32-slot gap. At the end, the last notified slot was 450079294 versus the independent end slot 450079335, a 41-slot gap. These comparisons are directional because the two RPCs have separate clocks/views, but they agree with the measured block-age delay.

The deterministic adapter decoded the first transaction signature from saved base64 bytes, including Solana transaction version 1's message-first signature tail, and produced receipt-clock-preserving frames explicitly marked `derived:blockSubscribe`. Independent official RPC indexing matched **7,481/7,481** signatures in fully observed interior slots 450079068–450079293, with no extra or missing signature. The pinned event decoder found 25 CreateEvents and 2,147 TradeEvents, with zero event layout errors. Supported native quotes passed 1,647 times with no material quote failure. This confirms a useful transaction-identified retrospective panel for this minute, not an actionable first-five-second feed.

The independent whole-second block timestamp-to-receipt median was **10.584 seconds**, p90 **11.051 seconds**; 25 CreateEvents had event-timestamp-to-receipt median **10.403 seconds**, p90 **10.872 seconds**. The frozen five-second timeliness gate failed. These are integer-second age proxies, not exact wire latency.

Twenty-nine successful transactions had an explicit `Log truncated` marker in the publicnode block metadata. Two native non-Mayhem state-continuity checks failed because large multi-sell transactions in slot 450079289 logged six `TradeEvent`s each, then logged a seventh `Sell` instruction before truncation; the next observed reserve state exposed the missing update. Signature completeness therefore does **not** imply complete lifecycle-event coverage. A later independent `getTransaction` check on the official Solana RPC verified **29/29** transaction identities and returned complete logs for all 29, revealing **14 additional TradeEvents**. This is a publicnode block-metadata limitation in the tested session; the extra events were available only at the later retrieval time and cannot be backdated as early features. The [saved responses and deterministic comparison](../data/mc008-truncated-log-recheck-20260924.tar.gz) have archive SHA-256 `2fb63d3b2b961c3dc830a6592f658c8d3edea0294fd1fd8335d74d4c4a80a4b5`. Twenty-five create transaction identities remain uncorroborated by a separately decoded `create_v2` account list in the current adapter. Preserve these as unknown and reject economic scoring on this cohort.

The block path fails the frozen latency and protocol-completeness requirements. It may serve as an independent transaction-level audit/backfill source, but it cannot substitute for a fast live feed. The next acquisition step is a dedicated stream or Geyser path with independent signature coverage, transaction identifiers, raw receive clocks and a longer burst window. If a program-level feed is used for earliest discovery, a separate transaction-level backfill must explicitly mark truncated or absent events rather than infer complete flow from logs.
