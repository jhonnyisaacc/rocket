# MC-022 frozen design — five-second unsigned Pump entry feasibility

Status: design frozen before the prospective cohort. MC-021 proved one later canonical sell could simulate with public inventory; this experiment asks whether a new Pump launch permits an unsigned buy simulation close to Rocket's five-second decision clock. It does not test ranking or actual inclusion.

## Universe and clocks

Run one bounded 180-second confirmed Pump `logsSubscribe` capture with the existing raw-frame collector (maximum 128 MiB) and an independent `getSignaturesForAddress` index audit. Decode `CreateEvent` with the pinned IDL. Exclude invalid-signature frames by the existing structural quarantine rule, recording their count; require signed transaction identity later for any selected create. Restrict diagnostic eligibility to successful native SOL-quoted, non-Mayhem creates observed in the raw stream. Select the **first five eligible distinct signatures in receive order**, without replacement after a simulation failure. Keep all creates and skipped reasons in the archive. Boundary-slot and identity failures remain visible and cannot be counted as covered core successes.

For each selected launch, target one account read at its frame receive time +5 seconds. Record target, actual dispatch and response times and the confirmed bank slot. Request Pump global, Pump Fees config, curve, mint, hypothetical buyer base ATA and hypothetical buyer native account in one `getMultipleAccounts` bank after preliminary mint/curve discovery. Reject a changed mint/curve identity or non-native quote. The fixed public buyer address is `HatUYhTtyCHruT9MoYxNKqw3A3wXYP43gsQoFbgqSsFZ`, which held more than 0.01 SOL at MC-021's selection clock. This is an unsigned simulation identity only; balance may change and is checked at each bank. No key or signature is used.

Use official `@pump-fun/pump-sdk` version 2.0.0, npm tarball SHA-256 `d535b8dd91003a6be036e4f61a71a71ee678e36134ef25f409dcf2d7b9a016d6`. Quote a **10,000,000-lamport** spend with the SDK's `getBuyTokenAmountFromSolAmount` using the same-bank global, fee, curve and mint supply. Request 99% of the quoted raw base amount (floor), with a fixed 10,100,000-lamport instruction maximum. Build `buy_v2` through the official SDK with the first global normal fee recipient and the first buyback recipient pinned in that SDK package. Add an idempotent buyer ATA create when absent, a 400,000 compute-unit limit and 100,000 micro-lamports per unit. Freeze these parameters across all five names, including those for which quoting or building fails.

For a built unsigned transaction, call confirmed `simulateTransaction` with `sigVerify=false`, `replaceRecentBlockhash=true`, and return the buyer native/base accounts and curve account. Preserve the full RPC request/response, logs, context slot, error, compute units and clocks. Define on-time as first same-bank request dispatched no later than receive +8 seconds and simulation response no later than receive +12 seconds. Report selection count, successful build, successful simulation, on-time successes, missing/error counts, quote and simulated token/cash deltas. The independent index and later signed create checks determine whether selected observations belong to a defensible covered core; never backdate those checks into the decision clock. A simulation is not a signed or landed Rocket order, and no instruction may be sent to the network.
