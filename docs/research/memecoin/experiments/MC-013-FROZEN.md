# MC-013 frozen design — contemporaneous curve-state quote validation

Parent MC-010/MC-012. MC-010's size-aware returns used the latest covered event state before 7-second entry and 67-second exit; a later pool lookup cannot establish alternate exit truth. This new prospective panel tests whether direct, time-stamped bonding-curve account reads corroborate the event-derived states at those clocks. It is a **read-only quote and acquisition calibration**, not a fill experiment or a new entry score.

Before collecting a fresh cohort, freeze a bounded 600-second Solana Labs `confirmed` Pump `logsSubscribe` capture (at most 512 MiB) and a concurrent read-only publicnode `getMultipleAccounts` companion (at most 32 MiB saved responses). Start the account companion as soon as the log collector starts. Parse raw log frames with the pinned Pump IDL and invocation stack, preserving every decoded CreateEvent and its actual frame-receipt clock. For **every** decoded creation, including native, nonnative, Mayhem and ultimately excluded names, schedule its emitted `bonding_curve` address for reads at receipt +7 and +67 seconds. Group due accounts in batches of at most 30. Save requested mint/address/phase/target, dispatch and response clocks, HTTP status, full JSON response, response hash, context slot and all errors. A failed or late call stays explicit; never infer a value from a later retry as if timely. Time the calls against *receipt*, not integer chain event time. If a notification cannot be decoded or lacks a curve address, retain it as unknown rather than silently dropping it. Continue until the primary capture manifest is final and all scheduled reads are attempted, with a hard 720-second companion bound.

Independently audit valid Pump signatures against the publicnode official transaction index, applying MC-010's prospectively frozen structural signature quarantine and requiring zero valid missing/extra signatures, successful-log truncation, decode errors, native state failures and material quote failures. Preserve all raw anomalies. The direct account response must have the Pump owner and pinned `BondingCurve` discriminator/layout; decode integer virtual/real reserve fields, completion, quote mint and fee fields from the saved account bytes. Compare account `context.slot` and receive clock with covered events, reporting conflicting/in-flight cases rather than forcing equality. Require a read whose dispatch starts no more than two seconds after its target for a **timely** snapshot; a response received more than five seconds after target is late for the frozen quote gate. These timing bounds are necessary screens, not proof of order inclusion.

For native non-Mayhem launches with full 67-second covered logs, strict later signed creation identity and both timely account snapshots, compute the same 10,000,000-lamport entry at seven seconds and stressed sell at 67 seconds using the pinned integer Pump formula, 200-bps slippage per leg, and 155,000/1,000,000-lamport network-fee scenarios per leg. Use only the latest fee parameters available by each quote response; no as-of fee source means `UNKNOWN`. A completed/depleted curve or failed sell remains route-specific `EXIT_UNAVAILABLE`, not realized zero recovery. Compare direct account state and quoted return against the unchanged event-state baseline, preserving any discrepancy and all excluded/unknown names. Report receipt age for every create, coverage and response clocks, quote-valid fractions, return/risk summaries and fee sensitivity. Do not retune the MC-005 flow score or change the seven/67-second horizons after observing this panel. A favorable subset cannot authorize `ENTER`: no hypothetical Rocket inclusion, PumpSwap or other DEX fill is measured.
