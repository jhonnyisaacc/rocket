# MC-023 frozen design — time, size and route-aware unsigned entry panel

Status: frozen before prospective capture. MC-022 found four timely unsigned buy simulation successes and one slippage failure among the first five native non-Mayhem launches. This panel broadens the decision-clock diagnostic across the full capture interval and pairs each selected launch with a contemporaneous exit-route read. It does not test a new rank or infer actual Rocket fills.

Run one 300-second confirmed Pump raw-log capture (maximum 192 MiB), plus an independent publicnode `getSignaturesForAddress` index audit with the same structural signature quarantine and interior-slot coverage rule used in MC-022. Preserve all frames, decoded creates, decode/index failures and full response clocks. Select successful native SOL-quoted, non-Mayhem `CreateEvent`s from raw frame receive order. Anchor five 60-second buckets to the saved subscription acknowledgement receipt. In each bucket select the first **four** eligible distinct signatures; never replace a selected name after RPC, quote, timing, identity or simulation failure. At most 20 names are selected, with bucket and ordinal saved. Boundary-slot names stay in the record but do not count as a covered-core success. Retrieve signed creation identity after the decision clock and never backdate it.

Within each bucket assign the four positions deterministically:

| Position | Target after CreateEvent receipt | SOL budget | Maximum quote |
| --- | --- | --- | --- |
| 0 | +5 seconds | 0.01 SOL | 1.01 × budget |
| 1 | +5 seconds | 0.05 SOL | 1.01 × budget |
| 2 | +8 seconds | 0.01 SOL | 1.01 × budget |
| 3 | +8 seconds | 0.05 SOL | 1.01 × budget |

For every selected name use official `@pump-fun/pump-sdk` 2.0.0 (npm tarball SHA-256 `d535b8dd91003a6be036e4f61a71a71ee678e36134ef25f409dcf2d7b9a016d6`) and the same public hypothetical payer, fee recipients, 99%-of-bank-quote token amount, ATA creation, 400,000-unit compute limit and 100,000 micro-lamports per unit as MC-022. The account input must be one confirmed bank containing Pump global, Pump Fees config, curve, mint, buyer ATA and buyer native account after preliminary address discovery. Build an unsigned `buy_v2` and call read-only `simulateTransaction` with signature verification off and blockhash replacement on. Preserve every RPC request/response, quote, transaction bytes, bank slot, program error and token/native account result. A scheduled attempt is on time when the bank request dispatch is at most target +3 seconds and simulation response at most target +7 seconds. Treat build/RPC errors, slippage failures and lateness as separate outcomes; no replacement or retuning.

In parallel, use the existing canonical route companion to read each eligible launch's Pump curve, derived PumpSwap pool and AMM config from one confirmed bank at CreateEvent receipt +67 seconds. Its first route request must dispatch within +2 seconds of target and return within +5; a present pool's second vault read must return within +8. Require a bank slot at or after creation and no later visible same-mint event beyond that bank. Join selected entry outcomes to the same-mint route response using signature and response clock. Report Pump curve sell-liquidity availability for the simulated token amount and canonical pool presence only when the direct account decodes and the read meets those timing and freshness gates. An unsigned successful buy is hypothetical inventory; the route read is hypothetical exit feasibility, not achieved cash. Do not assign a zero liquidation value when both routes are unavailable, because noncanonical venues remain unindexed. Do not compute a tradable net return without the appropriate same-bank fee state and actual fill evidence.

Primary outputs: full raw/index coverage and receipt age; eligible and selected denominators by bucket; signed identity status; quote/build/simulation status and timing by fixed cell; simulated base/native changes and error provenance; paired +67 direct curve/canonical route state with unknowns. The sample is descriptive, not randomized across sizes or delays, so cell differences are not causal estimates. No transaction may be signed or sent. Rocket execution stays disabled and `NO_EDGE_VALIDATED` remains the decision state.
