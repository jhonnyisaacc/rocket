# MC-009 frozen design — independent creation-feed receipt timing

Parent MC-008. This is an acquisition experiment, not a feature or trading strategy test. A capability probe confirmed that PumpPortal's `subscribeNewToken` websocket accepts a read-only connection without an API key and returns signature, mint and create metadata. Its [published data API](https://pumpportal.fun/data-api/bonk-fun-data-api/) describes creation notifications as free; trade subscriptions require a funded account and are outside this experiment. The MC-008 full block feed was independently complete but roughly ten seconds old at receipt and had truncated logs.

Before the prospective window, freeze **simultaneous 180-second** read-only captures of (a) PumpPortal `subscribeNewToken` and (b) Solana Labs `logsSubscribe` for the official Pump program at `confirmed` commitment. Start subscriptions within five seconds. Bound raw storage to 32 MiB and 192 MiB respectively. Preserve original JSON frames, UTC receive clocks, SHA-256, subscription acknowledgments, errors and exact interval bounds. Do not subscribe to token trades or make payments.

Audit the Solana log arm against `getSignaturesForAddress` from independent `solana-rpc.publicnode.com`, excluding its first/last observed slots. Parse successful pinned-IDL CreateEvents without using future information. Corroborate each PumpPortal candidate's signature, mint and chain slot with a later independent `getTransaction`; preserve null/error responses and retrieve times. Compare the two feeds only for signatures whose chain slots fall within the log arm's verified interior and whose receipts are away from the first/last five seconds of the common subscription interval. Report all chain creates missing from PumpPortal, all PumpPortal creates not corroborated in chain logs/transactions, mint mismatches and paired `PumpPortal minus Solana Labs` receipt times. Use the same frozen cohort for all counts; do not select favorable minutes or only matching names.

Report PumpPortal blockTime-to-receipt age with the independent whole-second block time, plus paired receipt median, p90, p99 and five-second tail counts. An unmatched or uncorroborated third-party notification is `UNKNOWN`, not a verified token launch. A fast feed is only an early-discovery candidate if chain corroboration and interior create coverage are exact, there is no capture error, and its create receipt-age p90 is at most five seconds. This short screen does not establish full lifecycle trade coverage or an executable entry; those need transaction-level reconciliation and a longer prospective window before an economic holdout. No signer or order endpoint is involved.
