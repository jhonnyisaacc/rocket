# MC-020 frozen design — landed PumpSwap sell accounting after migration

Parent MC-017/MC-019. Question: do signed, landed transactions on the three MC-017 canonical pools expose a verifiable size, fee and vault accounting path for sells? This calibrates an observed protocol route; it does not measure a hypothetical Rocket fill or validate an entry rank.

Selection is fixed by MC-017 route report SHA-256 `b9908c92251575049a9451f2a8235724edbe62fc8ca87ebbbfefd618cacff4b2`: all three `CANONICAL_POOL_VAULTS_DECODED` rows. For each pool, query confirmed `getSignaturesForAddress` in reverse slot order, paging with `before` until a page reaches the MC-017 **second** read's context slot, or a hard 500-signature/ten-page bound. Save every page, exact response bytes, request/receive clocks, and errors. Require a page to reach the boundary for coverage; otherwise mark that pool incomplete and do not infer an earliest signature. Select the **earliest 20 successful signatures** strictly after that pool's second-read slot, ordered by `(slot, signature)`; retain the count of failed and unselected signatures in the covered interval. Fetch `getTransaction` for every selected signature using `json` encoding and `maxSupportedTransactionVersion: 0`, preserving null/error replies, exact response bytes and clocks. Do not retry unboundedly or replace an unavailable selected transaction.

Decode PumpSwap `SellEvent` from the pinned AMM IDL SHA-256 `2091433899b07d003d98118ae6cd3c628960fd393b40710b6e15bce6d0e7f2d1` only when the transaction is successful, its signature/slot matches the index, the log invocation is attributable to PumpSwap, and event bytes conform to a known version; unknown trailing bytes or unsupported formats remain undecoded. Every selected transaction stays in the denominator. For each decoded sell, compare event pool/mint/vault identities to the frozen pool, its explicit base amount, quote amount, LP/protocol/creator fee bps and amounts, `user_quote_amount_out`, and signed metadata pre/post vault and user token balances. Mark absent pre/post balance data, multiple same-vault swaps, routed side effects or incompatible event version as ambiguous rather than forcing a one-event reconciliation. Report network fee and compute units for observed landed transactions as **observational** values only.

Success for this diagnostic requires complete index coverage for each pool's selected interval and a known denominator, with any decoded sell's accounting cross-checked at transaction level. It does not require a sell to exist in a tiny window; zero sells is an explicit inconclusive result for arithmetic. No historical fee state is backdated from MC-019. The next falsifier remains an amount-specific unsigned instruction simulation at a new contemporaneous state and, separately, actual Rocket inclusion/fill evidence. No signed or live Rocket order is sent.
