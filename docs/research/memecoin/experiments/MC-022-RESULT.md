# MC-022 result — five-second unsigned Pump buy simulation

Status: **accepted for a bounded read-only entry feasibility measurement**, not for Rocket inclusion or an economic entry rule. The [frozen design](MC-022-FROZEN.md) was committed and pushed before the prospective capture. The first collector launch failed before session creation because the repository virtual environment lacked its declared `websockets` dependency; the unchanged design was run with the workspace Python runtime, which had `websockets` 15.0.1. No launch was selected from the failed attempt.

The 180-second confirmed Pump log stream saved 13,462 notifications and 73 decoded `CreateEvent`s. A separate publicnode `getSignaturesForAddress` index matched **13,443/13,443 valid interior-slot signatures**, with zero missing in either direction, zero quarantined frames, zero event decoder errors and no truncated successful log frames. The independent index and raw capture replayed byte for byte from the archive. Whole-second block-time-to-receipt age across those interior signatures had median 1.154 seconds and p90 1.609 seconds; this is a coarse age measure, not network latency. All five selected creations lay in covered interior slots and later passed strict signed transaction mint/slot identity checks. Those later reads did not make identity available at the five-second decision clock.

The first five native, non-Mayhem creates in receive order were each quoted from a confirmed bank using official Pump SDK 2.0.0 and the fixed 10,000,000-lamport budget. All five built unsigned `buy_v2` transactions and reached read-only `simulateTransaction`. One-bank requests were dispatched 5.509–6.581 seconds after CreateEvent frame receipt; simulation responses arrived 6.171–7.425 seconds after receipt. All five met the frozen +8/+12-second timing gate. **Four of five simulations succeeded**, and their simulated buyer token-account increases exactly equaled the prespecified 99%-of-quote token amounts. Each response reported a 45,000-lamport network fee and 103,865–117,364 consumed compute units among successes. The buyer's total simulated native debit included token-account rent and must not be read as pure purchase price. No transaction was signed or broadcast.

The one failed outcome was selection index 3, mint `DT2d27jA11ueNyiCixeFhNAgd9LQUZNCsnn5c2rgpump`. Its simulation returned Pump `TooMuchSolRequired` (custom error 6002). The saved log says the buy needed **10,532,647 lamports**, above the frozen **10,100,000-lamport** instruction maximum, despite a 1% reduction from the bank's quoted token amount. Its quote bank was slot 450361817 and simulation bank was slot 450361820; state moved enough across those slots to violate the cost cap. This is an observed read-only slippage failure for the selected amount, not a landed failed order. It remains in the five-name denominator.

The result demonstrates that current official SDK instructions can be assembled and simulated by the decision clock for this small, covered sample, and that quote movement can invalidate one even within about one second of the state read. It does not estimate a general inclusion probability from five feasibility-selected launches, show that Rocket could sign or land at those times, measure a real fee auction, or establish a profitable entry. It leaves actual exit inventory and recovery unmeasured. The next read-only execution test should preserve more launch and size/latency strata, reprice without retuning this cohort, and connect entry simulation failures to later route availability; actual landing/settlement remains separately unauthorized. No rank is promoted and `rocket memecoin scan` stays `NO_EDGE_VALIDATED`.
