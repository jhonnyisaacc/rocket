# MC-008 frozen design — transaction-identified block stream feasibility

Parent MC-007. Infrastructure test only. The two public `logsSubscribe` aliases shared one uncorroborated signature and earlier long sessions had 10–45-second receipt-age bursts. A preliminary capability probe found that `wss://solana-rpc.publicnode.com` supports read-only `blockSubscribe` with full base64 transactions and version 1, whereas both official public aliases rejected this method. The earlier publicnode *log* subscription failed coverage; the block feed is a distinct acquisition mode and must earn its own validation.

Before collecting the prospective session, freeze one **60-second**, at most **384 MiB** `confirmed` Pump-program `blockSubscribe` session using `transactionDetails: full`, base64 encoding, transaction version 1 and no rewards. Preserve original frames, receipt clocks, segment checksums, subscription/termination errors and the first/last block slot. Decode each transaction's first signature from its signed wire bytes, retain transaction order and metadata, and create a clearly marked derived log frame for reuse of the pinned Pump decoder. A derived frame inherits the original block frame's receipt clock; it is never presented as a direct `logsSubscribe` message. Reject malformed signatures or inconsistent transaction and metadata counts. Preserve raw-to-derived provenance and all failed transactions.

Index every fully observed interior slot using `getSignaturesForAddress` from **`api.mainnet-beta.solana.com`**, which is independent of the block feed. Require exact signature coverage, zero transaction identity/decoder/quote failures and no collector error before any economic analysis. Exclude first and last block slots as boundary uncertainty. Measure block and CreateEvent timestamp-to-receipt distributions, error counts, raw volume and decoding throughput. Whole-second block/event clocks are age proxies, not wire latency. The index and all raw responses must be archived for offline replay.

The block path is eligible for a longer validation only if it meets exact independent coverage, has no collector or identity error, and CreateEvent receipt-age p90 at most five seconds. A 60-second pass is necessary, not proof of 24/7 timely service or an economic edge. If it fails, report the failure and investigate another dedicated stream or provider. Do not select a favorable subwindow or run a strategy holdout on an uncovered feed. No signer or order path is involved.
