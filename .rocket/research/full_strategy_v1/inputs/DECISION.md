# Final decision — reconcile the existing strategy, do not invent another one

## Outcome

**A concrete source-to-code mismatch is established. A profitable remedy is not.** The project already documents a richer strategy than Rocket's six-candle proxy or our immediate/passive-entry experiment. We should stop describing results from those proxies as tests of the entire momentum/Cryptopana theory.

The existing refined process is: higher-timeframe premise → four-hour pullback into an identified confluence zone → structural reaction → separate one-hour entry trigger → thesis-based invalidation and confluence objectives. The early source pass in this session did not inspect the later refinements. That gap was corrected before handoff, with the original sealed chart judgments retained rather than rewritten.

## Three findings that move the research forward

1. **The intended pullback logic is already written down.** `technical.yaml:707` says a four-hour counter-move can be the setup, not an invalidation, and warns against substituting four-hour moving-average agreement. Current Rocket uses six directional high/low candles. Current Nave's `four_h_setup_valid` still uses moving-average agreement. These are demonstrably different definitions, even before considering returns.
2. **Entry geometry is being mistaken for trigger validation.** A synthetic test of Nave's `one_h_entry` returns entry/stop/targets for 24 flat hourly candles with no flip or sweep; it also returns geometry with only one hourly bar. That does not prove the full legacy engine would trade the fixture, but it proves this helper does not certify the documented trigger. Rocket's structure function is a candidate detector, not this execution layer. Our passive touch entry is a simulator convention.
3. **The target needs to exist before we judge reward.** The transcript recommends at least 1R to the first confluence. Later project notes and legacy code already discuss/implement structural targets, but the helper can skip a nearer swing below 1R and fabricate fixed-R fallbacks. That differs from locating the first credible objective and then deciding whether the trade has enough room. Neither formula nor target naming establishes confluence or edge.

The recovered notes contain prior backtest-driven refinements and internal inconsistencies. They are available specifications to reconcile, not an independently validated strategy to deploy unchanged. Documentation/header drift is also recorded: the actual legacy daily/4h windows differ from the header, and its actual no-daily target fallback differs from the docstring.
